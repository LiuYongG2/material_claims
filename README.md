# 工程物资领料履约诊断与提前阻断规则

> 仅使用题目发放的 `material_claims.csv`（1263 行），**无任何补造数据**。
> 成本口径（题目给定）：每次现场缺料空跑损失 **90 工时**；每提前阻断一次调拨花费 **15 工时**。

## 我的判断

### 看到了什么（均由脚本从数据算出）

1. **数据质量**（`analysis.py` 清洗环节输出）：原始 1263 行 → `claim_id` 重复 **60 行**（同号保留首次）→ 剔除 `is_fulfilled` 缺失 **46 行** → 有效样本 **1157 行**（落空 136 / 履约 1021，整体履约率 **88.25%**）。
2. **时区陷阱**：`requested_at` 带 `+08:00` 偏移，`stock_synced_at` 是 UTC（`Z`）。直接相减会把同步滞后多算约 8 小时，必须统一到 UTC 再算。
3. **落空组的库存同步滞后显著更长**：落空中位数 **29 分钟** vs 履约 **9 分钟**（均值 31.4 vs 13.8 分钟）；同时落空组账面库存更低（中位 11 vs 15）、仓库更忙（当日单量中位 55 vs 52）。滞后是最强的单一信号。

### 根问题

领料员看到的 `stock_qty` 是 `stock_synced_at` 时刻的账面快照。从同步到提交申请之间隔得越久，这个数字越不可信——期间发生的出库/调拨都没反映进来。叠加仓库当日繁忙造成的出库竞争，就出现"系统显示有货、到现场却没料"的空跑。**根问题不是库存绝对量少，而是库存信息陈旧（同步滞后），库存数字在滞后窗口内失真。**

## 做了什么

1. **数据清洗**：时区统一（全部转 UTC 后计算 `sync_lag_min`）、按 `claim_id` 去重、剔除标签缺失行。
2. **根因诊断**：对比落空/履约两组在 `sync_lag_min`、`stock_qty`、`day_orders` 上的分布（见上文数字），并分仓/分品类输出履约率。
3. **可执行阻断规则**：对 `sync_lag_min` 做 0~65 分钟网格扫描，目标函数 = 命中落空数 × 90 − 阻断次数 × 15，取净节省最大的阈值。
4. **防过拟合验证**：按申请时间前 70% 训练选阈值、后 30% 测试，验证规则在未见过的时间段依然有效。
5. **产出**：`outputs/metrics.json`（全部指标）、`outputs/unfulfilled_cases.csv`（落空样本明细，供现场复盘）。

## 怎么证明有用（数字）

### 不做任何干预的基线

- 136 次空跑 × 90 工时 = **12240 工时**损失（全量有效样本）。

### 最优阻断规则：`sync_lag_min >= 14` 时提前阻断调拨

| 指标 | 数值 |
|---|---|
| 触发阻断 | 326 单（占 28.2%） |
| 命中真实落空 | 105 单 |
| 误伤（本可履约却被拦） | 221 单 |
| 精确率 / 召回率 | 0.322 / 0.772 |
| 成本 | 326×15 = 4890 工时 |
| 避免的空跑损失 | 105×90 = 9450 工时 |
| **净节省** | **4560 工时**（相对基线 12240 工时，挽回 37.3%） |

### 时间切分验证（防"在同一份数据上自说自话"）

- 按 `requested_at` 排序，前 809 单训练、后 348 单测试。
- 训练集独立选出的最优阈值同样是 **lag ≥ 14**（训练净省 3285 工时）。
- 在后 30% 未参与选阈值的数据上：触发 83 单、命中 28、精确率 0.337、召回 0.700、**净节省 1275 工时**（测试集基线 3600 工时）。
- 结论：规则在时间段外推下依然稳定为正收益，不是样本内巧合。

### 业务含义

把"库存快照超过 14 分钟未同步"的申请单拦截下来、先做一次调拨核实（花 15 工时），比放任作业队到现场空跑（损失 90 工时）划算得多。同步滞后 ≥ 14 分钟的申请里约 1/3 最终会落空——账面数字在 14 分钟后开始明显失真，这就是可以动手的阈值。

## 如何复现

```bash
# 1. 环境（Python >= 3.9）
pip install -r requirements.txt

# 2. 运行（脚本自动在 data/ 或仓库根目录找 material_claims.csv）
python analysis.py

# 3. 查看结果
#    outputs/metrics.json          —— 全部指标（清洗、诊断、规则扫描、时间切分验证）
#    outputs/unfulfilled_cases.csv —— 落空样本明细
```

Windows 下若控制台中文乱码，先执行 `chcp 65001` 再运行（`outputs/` 文件本身始终是 UTF-8，不受控制台影响）。
